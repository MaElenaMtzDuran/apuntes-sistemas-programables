# 1.3 Prácticas

## <mark style="color:$success;">**1.3.1 GPIO, botón y parpadeo no bloqueante (Arduino Uno)**</mark>

### **Objetivo**

Configurar entradas y salidas digitales en la Arduino Uno (ATmega328P); leer un botón y controlar dos LED, distinguiendo entrada, salida y antirrebote básico, primero con funciones Arduino y después con acceso directo a registros del ATmega328P.

### Material y equipo <a href="#material-y-equipo" id="material-y-equipo"></a>

* Arduino Uno Rev3 (o compatible con ATmega328P) y cable USB;
* Protoboard;
* 2 LED, 2 resistencias de 330 Ω;
* Botón, resistencia de 10 kΩ (o uso de la resistencia de pull-up interna del ATmega328P);
* Cables de puente;
* Multímetro.

### Marco teórico breve <a href="#marco-terico-breve" id="marco-terico-breve"></a>

`pinMode(pin, OUTPUT/INPUT)` configura la dirección de un pin; internamente escribe el bit correspondiente del registro `DDRx` del puerto al que pertenece ese pin. Un botón mecánico rebota; una transición puede parecer varias. Se usará una espera corta sólo para antirrebote y `millis()` (no `delay()`) para el parpadeo no bloqueante.

### Esquema descrito <a href="#esquema-descrito" id="esquema-descrito"></a>

1. LED1: pin digital **D8** → resistencia de 330 Ω → ánodo LED1; cátodo a GND.
2. LED2: pin digital **D9** → resistencia de 330 Ω → ánodo LED2; cátodo a GND.
3. Botón: un terminal a pin digital **D2**, el otro terminal a GND; usar la resistencia de pull-up interna del ATmega328P (`INPUT_PULLUP`) o, alternativamente, una resistencia externa de 10 kΩ de D2 a +5 V con el botón hacia GND.
4. Alimentación de la placa por el propio cable USB; no se requiere fuente externa ni circuito de reset discreto, ya que la Arduino Uno los integra.

<figure><img src="../../.gitbook/assets/image (4).png" alt="" width="366"><figcaption><p>Figura 1.30 Diagrama de conexión en Tinkercad Leds-Botón</p></figcaption></figure>

### Procedimiento <a href="#procedimiento" id="procedimiento"></a>

1. Abrir el Arduino IDE y crear un nuevo sketch; seleccionar la placa "Arduino Uno" y el puerto serie correspondiente.
2. Configurar D2 como entrada con pull-up, y D8/D9 como salidas mediante `pinMode()`.
3. Implementar el parpadeo de LED1 cada 500 ms usando `millis()` (no bloqueante) y la detección de flanco del botón para alternar LED2 con antirrebote por tiempo.
4. Compilar (verificar) y revisar los mensajes del compilador en la consola del IDE.
5. Cargar el programa por USB (el bootloader de la Uno gestiona la programación sin necesidad de un programador ICSP externo).
6. Medir con el multímetro la tensión en D8/D9 en alto y en bajo.
7. Registrar el periodo real de parpadeo de LED1 contra un cronómetro y calcular el error respecto a 500 ms.
8. **Bonus de registros:** repetir el paso 2 sustituyendo `pinMode()`/`digitalWrite()` por manipulación directa de `DDRB`, `PORTB` y `PIND` (ver código de registros abajo) y confirmar que el comportamiento observado es idéntico.

### **Código de ejemplo (Arduino IDE, funciones de alto nivel)**

```cpp
const uint8_t PIN_LED1 = 8;
const uint8_t PIN_LED2 = 9;
const uint8_t PIN_BOTON = 2;

unsigned long ultimoCambio = 0;
const unsigned long PERIODO_MS = 500;
bool estadoLed1 = false;
int anterior = HIGH;
unsigned long ultimoAntirrebote = 0;
const unsigned long ANTIRREBOTE_MS = 30;

void setup() {
  pinMode(PIN_LED1, OUTPUT);
  pinMode(PIN_LED2, OUTPUT);
  pinMode(PIN_BOTON, INPUT_PULLUP);   // botón a GND, pull-up interno activado
}

void loop() {
  unsigned long ahora = millis();

  // Parpadeo no bloqueante de LED1
  if (ahora - ultimoCambio >= PERIODO_MS) {
    ultimoCambio = ahora;
    estadoLed1 = !estadoLed1;
    digitalWrite(PIN_LED1, estadoLed1);
  }

  // Lectura de botón con antirrebote por tiempo
  int actual = digitalRead(PIN_BOTON);
  if (actual != anterior && (ahora - ultimoAntirrebote) > ANTIRREBOTE_MS) {
    ultimoAntirrebote = ahora;
    if (actual == LOW) {              // flanco de bajada: botón presionado
      digitalWrite(PIN_LED2, !digitalRead(PIN_LED2));
    }
    anterior = actual;
  }
}
```

**Código equivalente por acceso directo a registros (competencia de registros)**

```cpp
// Equivalente de bajo nivel: D8/D9 pertenecen a PORTB (PB0, PB1); D2 pertenece a PORTD (PD2)
void setup() {
  DDRB |= (1 << PB0) | (1 << PB1);   // D8, D9 como salida
  DDRD &= ~(1 << PD2);               // D2 como entrada
  PORTD |= (1 << PD2);               // pull-up interno en D2
}

void loop() {
  static unsigned long ultimoCambio = 0;
  unsigned long ahora = millis();
  if (ahora - ultimoCambio >= 500) {
    ultimoCambio = ahora;
    PORTB ^= (1 << PB0);              // alterna D8 directamente en el registro
  }
  if (!(PIND & (1 << PD2))) {         // lectura directa del pin D2
    PORTB ^= (1 << PB1);
    delay(30);                        // antirrebote simple para el ejemplo de registros
  }
}
```

## <mark style="color:$success;">**1.3.2 Adquisición ADC y transmisión serie (Arduino Uno)**</mark>

### Objetivo <a href="#objetivo" id="objetivo"></a>

Muestrear una tensión analógica con el ADC de 10 bits del ATmega328P, convertirla a milivoltios y transmitir el resultado por el puerto serie a una terminal (Monitor Serie del IDE), primero con `analogRead()` y después con acceso directo a los registros `ADMUX`/`ADCSRA`.

### Material y equipo <a href="#material-y-equipo" id="material-y-equipo"></a>

* Montaje base de la práctica 1 (Arduino Uno);
* Potenciómetro de 10 kΩ;
* Cable USB (la misma conexión USB provee la comunicación serie con la PC, sin adaptador externo);
* Arduino IDE con el Monitor Serie, multímetro.

### Marco teórico breve <a href="#marco-terico-breve" id="marco-terico-breve"></a>

El potenciómetro produce 0–5 V. El ADC del ATmega328P usa por defecto AVCC (≈5 V en la Uno) como referencia y entrega un valor de 0 a 1023 (10 bits). `analogRead()` selecciona el canal, espera la adquisición e inicia la conversión internamente, escribiendo los registros `ADMUX` y `ADCSRA`. La comunicación serie por USB usa el puerto UART0 del ATmega328P a través del chip convertidor USB-serie integrado en la placa; no se requiere un adaptador USB-UART aparte como en un microcontrolador aislado.

### Esquema descrito <a href="#esquema-descrito" id="esquema-descrito"></a>

1. Potenciómetro: extremos a 5V y GND; cursor al pin analógico **A0**.
2. Ninguna conexión adicional de UART es necesaria: la comunicación serie usa el mismo cable USB con el que se programa la placa.
3. Mantener el montaje de LED/botón de la práctica 1 si se desea reutilizar la placa.

<figure><img src="../../.gitbook/assets/image (5).png" alt="" width="370"><figcaption><p>Figura 1.31 Diagrama de conexión en Tinkercad Potenciómetro</p></figcaption></figure>

### Procedimiento <a href="#procedimiento" id="procedimiento"></a>

1. Conectar el cursor del potenciómetro a A0.
2. En el sketch, leer A0 con `analogRead()` cada 250 ms.
3. Calcular milivoltios con aritmética de 32 bits: `mV = (adc * 5000UL) / 1023UL`.
4. Enviar por `Serial` el valor crudo del ADC y los milivoltios calculados, a 9600 baudios.
5. Abrir el Monitor Serie del IDE a 9600 baudios y registrar cinco posiciones del potenciómetro.
6. Medir las mismas posiciones con el multímetro y calcular el error absoluto y porcentual.
7. Repetir promediando 16 muestras (oversampling) y comparar la estabilidad de la lectura.
8. **Bonus de registros:** sustituir `analogRead()` por una rutina propia que configure `ADMUX` (canal 0, referencia AVCC) y `ADCSRA` (habilitación, prescaler, inicio de conversión y espera de la bandera `ADIF`), y comparar el resultado con el de `analogRead()`.

### Código de ejemplo (Arduino IDE, funciones de alto nivel) <a href="#cdigo-de-ejemplo-arduino-ide-funciones-de-alto-niv" id="cdigo-de-ejemplo-arduino-ide-funciones-de-alto-niv"></a>

```c++
const uint8_t PIN_POT = A0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  uint32_t suma = 0;
  for (uint8_t i = 0; i < 16; i++) {
    suma += analogRead(PIN_POT);
    delay(1);
  }
  uint16_t adc = (uint16_t)(suma / 16);
  uint16_t mv = (uint16_t)(((uint32_t)adc * 5000UL) / 1023UL);

  Serial.print("ADC=");
  Serial.print(adc);
  Serial.print(", V=");
  Serial.print(mv);
  Serial.println(" mV");

  delay(250);
}
```

Código equivalente por acceso directo a registros (competencia de registros)

```cpp
// Lectura de A0 (ADC0) manipulando ADMUX/ADCSRA directamente, sin analogRead()
void setup() {
  Serial.begin(9600);
  ADMUX = (1 << REFS0);              // Referencia AVCC, canal ADC0 (A0)
  ADCSRA = (1 << ADEN) | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0); // ADC on, prescaler 128
}

uint16_t leerADC0(void) {
  ADCSRA |= (1 << ADSC);             // inicia conversión
  while (ADCSRA & (1 << ADSC)) { }   // espera a que termine
  return ADC;                        // registro combinado ADCL/ADCH
}

void loop() {
  uint16_t adc = leerADC0();
  uint16_t mv = (uint16_t)(((uint32_t)adc * 5000UL) / 1023UL);
  Serial.print("ADC(reg)=");
  Serial.print(adc);
  Serial.print(", V=");
  Serial.print(mv);
  Serial.println(" mV");
  delay(250);
}
```

## <mark style="color:$success;">**1.3.3 Temporizador, interrupción y LCD 16×2 (Arduino Uno)**</mark>

### Objetivo <a href="#objetivo" id="objetivo"></a>

Generar una base de tiempo con el Timer1 del ATmega328P en modo de interrupción y mostrar en un LCD 16×2 un contador de segundos, sin usar `delay()` para la temporización principal, contrastando la implementación con `attachInterrupt()`/registros directos.

### Material y equipo <a href="#material-y-equipo" id="material-y-equipo"></a>

* Arduino Uno y montaje base;
* LCD 16×2 compatible HD44780;
* Potenciómetro de 10 kΩ para contraste;
* Resistencia para retroiluminación según el módulo (300 Ω);
* Biblioteca `LiquidCrystal` (incluida en el Arduino IDE);
* Cable USB; analizador lógico u osciloscopio opcional.

### Marco teórico breve <a href="#marco-terico-breve" id="marco-terico-breve"></a>

Con el reloj de 16 MHz de la Arduino Uno, el Timer1 (16 bits) con prescaler 1:64 recibe 250 kHz, es decir, un tick cada 4 µs; para 10 ms se requieren 2 500 cuentas, por lo que la precarga en modo comparación (`OCR1A`) es 2 499 (cuenta desde 0). Cien interrupciones forman un segundo. La interrupción sólo actualiza contadores; la escritura del LCD se realiza en `loop()`.

### Esquema descrito <a href="#esquema-descrito" id="esquema-descrito"></a>

LCD en modo 4 bits, usando la biblioteca `LiquidCrystal` con el mapeo `LiquidCrystal lcd(RS, E, D4, D5, D6, D7)`:

* VSS→GND, VDD→5V.
* VO→cursor del potenciómetro de contraste; extremos a 5V y GND.
* RS→pin digital **7**; E→pin digital **6**; RW→GND.
* D4→pin **5**, D5→pin **4**, D6→pin **3**, D7→pin **2**.
* Retroiluminación (A/K) según especificación del módulo, con resistencia limitadora si es necesaria. Conecta el ánodo a **5V** mediante resistencia de 300 Ω) y el cátodo a **GND.**

<figure><img src="../../.gitbook/assets/image (6).png" alt="" width="563"><figcaption><p>Figura 1.32 Diagrama de conexión en Tinkercad Pantalla LCD</p></figcaption></figure>

### Procedimiento <a href="#procedimiento" id="procedimiento"></a>

1. Calcular y documentar la precarga de `OCR1A` para una interrupción cada 10 ms.
2. Declarar el objeto `LiquidCrystal lcd(7, 6, 5, 4, 3, 2);` e inicializarlo con `lcd.begin(16, 2)`.
3. Configurar el Timer1 en modo CTC (Clear Timer on Compare) con `OCR1A` y habilitar la interrupción `TIMER1_COMPA_vect` mediante registros (`TCCR1B`, `TIMSK1`), ya que el lenguaje Arduino no ofrece una función de alto nivel para temporizadores de hardware equivalente a `attachInterrupt()` en pines externos.
4. Verificar con el analizador lógico u osciloscopio, si está disponible, que el periodo de interrupción es de 10 ms.
5. Mostrar `Tiempo: n s` en el LCD sólo cuando cambie el contador de segundos (no en cada iteración del `loop()`).
6. Cargar el programa y comparar 60 s del contador contra un cronómetro externo.
7. Calcular la deriva porcentual y discutir la precisión del resonador cerámico de la Uno frente a un cristal de cuarzo.
8. Forzar deliberadamente una operación lenta (por ejemplo, `delay(50)`) dentro de la rutina de interrupción y explicar por qué esto es incorrecto en una ISR.

### Código de ejemplo (Arduino IDE, con Timer1 por registros y LCD por biblioteca) <a href="#cdigo-de-ejemplo-arduino-ide-con-timer1-por-regist" id="cdigo-de-ejemplo-arduino-ide-con-timer1-por-regist"></a>

```c++
#include <LiquidCrystal.h>

LiquidCrystal lcd(7, 6, 5, 4, 3, 2);

volatile uint8_t ticks10ms = 0;
volatile uint16_t segundos = 0;
volatile uint8_t actualizar = 0;

void configurarTimer1(void) {
  noInterrupts();
  TCCR1A = 0;
  TCCR1B = 0;
  TCNT1  = 0;
  OCR1A  = 2499;                       // 10 ms con prescaler 1:64 a 16 MHz
  TCCR1B |= (1 << WGM12);              // modo CTC
  TCCR1B |= (1 << CS11) | (1 << CS10); // prescaler 64
  TIMSK1 |= (1 << OCIE1A);             // habilita interrupción por comparación
  interrupts();
}

ISR(TIMER1_COMPA_vect) {
  if (++ticks10ms >= 100) {
    ticks10ms = 0;
    segundos++;
    actualizar = 1;
  }
}

void setup() {
  lcd.begin(16, 2);
  lcd.print("Tiempo:");
  configurarTimer1();
}

void loop() {
  if (actualizar) {
    noInterrupts();
    uint16_t copia = segundos;
    actualizar = 0;
    interrupts();

    lcd.setCursor(0, 1);
    lcd.print(copia);
    lcd.print(" s   ");
  }
}
```

## <mark style="color:$success;">**1.3.4 Conmutación y Multiplexación de Displays de 7 Segmentos (Ánodo Común)**</mark>

### **Objetivo**

### Material y equipo <a href="#material-y-equipo" id="material-y-equipo"></a>

* Placa Arduino,&#x20;
* 2 displays de 7 segmentos de ánodo común,&#x20;
* 14 resistores de 330 Ω (bus de datos),&#x20;
* 2 resistores de 220 Ω (selector de display).



* **Diagrama de conexión propuesto**:

<figure><img src="../../.gitbook/assets/image (3).png" alt="" width="375"><figcaption><p>Figura 1.33 Diagrama de conexión en Tinkercad Displays de 7 segmentos</p></figcaption></figure>

### Procedimiento <a href="#procedimiento" id="procedimiento"></a>

1. Conectar los display's de acuerdo al esquema anexo.
2. Abrir el Arduino IDE y crear un nuevo sketch; seleccionar la placa "Arduino Uno" y cargar el código anexo.
3. Compilar (verificar) y revisar los mensajes del compilador en la consola del IDE.
4. Cargar el programa por USB.
5. Registrar el periodo real de conteo de cada uno de los display's y el margen de error.

### **Código de Ejemplo (Multiplexado Directo):**

```cpp
// Códigos de 7 segmentos para dígitos 0-9 (Ánodo común, lógicos en BAJO encienden)
const uint8_t digitos[] = {
  0xC0, // 0
  0xF9, // 1
  0xA4, // 2
  0xB0, // 3
  0x99, // 4
  0x92, // 5
  0x82, // 6
  0xF8, // 7
  0x80, // 8
  0x90  // 9
};

const int pinDigit1 = 10; // Habilitador del dígito izquierdo (decenas)
const int pinDigit2 = 11; // Habilitador del dígito derecho (unidades)
int contador = 0;
unsigned long tiempoAnterior = 0;

void setup() {
  // Configurar puerto D completo como salida para los segmentos (pines 0 a 7 de Arduino)
  DDRD = 0xFF;
  pinMode(pinDigit1, OUTPUT);
  pinMode(pinDigit2, OUTPUT);
  digitalWrite(pinDigit1, HIGH); // Apagados inicialmente
  digitalWrite(pinDigit2, HIGH);
}

void loop() {
  // Incrementar contador cada 500 ms de manera no bloqueante
  if (millis() - tiempoAnterior >= 500) {
    tiempoAnterior = millis();
    contador = (contador + 1) % 100;
  }

  // Desglose de dígitos
  int decenas = contador / 10;
  int unidades = contador % 10;

  // Mostrar Decenas
  PORTD = digitos[decenas];       // Carga dato en el bus
  digitalWrite(pinDigit1, LOW);   // Enciende display decenas (PNP activa en LOW)
  delay(5);                       // Retardo para persistencia visual
  digitalWrite(pinDigit1, HIGH);  // Apaga display decenas para evitar sombras

  // Mostrar Unidades
  PORTD = digitos[unidades];      // Carga dato en el bus
  digitalWrite(pinDigit2, LOW);   // Enciende display unidades
  delay(5);                       // Retardo para persistencia visual
  digitalWrite(pinDigit2, HIGH);  // Apaga display unidades
}
```
